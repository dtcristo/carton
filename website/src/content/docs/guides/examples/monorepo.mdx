Directories alone do not enforce boundaries between an app's domains. Here each domain is a Gem Carton: a path gem with declared runtime gems, an Interior, and a Public Surface. Each runs in its own Carton Box, with Bundler selecting its gem versions ([#32](https://github.com/dtcristo/carton/issues/32)). [Source on GitHub](/guides/examples/monorepo/).

```
Gemfile                    # carton, the three Cartons, bigdecimal 4.1.1
main.rb                    # Carton.setup_bundle, then import each Carton
cartons/
  pricing/
    pricing.gemspec        # depends on bigdecimal
    lib/pricing.rb         # Entrypoint: export Pricing
  billing/
    billing.gemspec        # depends on pricing
    lib/billing.rb         # Pricing = import 'pricing'
  shipping/
    shipping.gemspec       # only depends on carton
    lib/shipping.rb
```

- One `Gemfile` and `Gemfile.lock` cover the whole monorepo and pin every third-party version.
- `import 'billing'` loads a Carton by gem name in its own Carton Box. Only its Export crosses back.
- `bigdecimal` loads inside `pricing`'s Box at the locked version, not in the Main Box.

A Carton can leave the monorepo as a published gem without changes, since it already is one.

## Undeclared Gems

A Gem Carton imported by a bundled Importer sees the Importer's whole lockfile, as `Bundler.setup` gives the Main Box. The example declares every runtime gem and passes `carton check`. To see an Undeclared Gem reported, temporarily add `Shipping = import 'shipping'` inside the `Billing` module in `cartons/billing/lib/billing.rb`, then run:

```sh
cd examples/monorepo
bundle exec ruby ../../carton-tools/exe/carton check main.rb
# cartons/billing/lib/billing.rb:<line>: error: import 'shipping' loads the
# shipping gem, which billing's gemspec does not declare: add
# spec.add_dependency 'shipping'
```

That import would work at runtime even though `billing.gemspec` does not declare it. Enforcing declarations at runtime too is proposed in [#38](https://github.com/dtcristo/carton/issues/38) as strict Gem Cartons.

## Tests

`test/` shows both ways to test a Carton, under the monorepo's bundle:

- `test/pricing_test.rb` is a unit test. It loads `pricing` with plain `require`, so there is no Box or boundary, and tests the private `Pricing::Rounding` through `Pricing.const_get(:Rounding)`. It runs with or without `RUBY_BOX=1`.
- `test/app_test.rb` is an integration test. It imports `billing` and `pricing` as `main.rb` does, tests their Public Surfaces, and checks that `Pricing::Rounding` and `bigdecimal` stay hidden.

Each file runs in its own process, since the unit test's `require` would load a Second Copy of `pricing` beside the imported one.

```sh
ruby examples/monorepo/test/pricing_test.rb
RUBY_BOX=1 ruby examples/monorepo/test/app_test.rb
```

## Run

```sh
bundle exec rake example:monorepo
RUBY_BOX=1 ruby examples/monorepo/main.rb
```
