How each imported Carton loads its gems with Bundler. Use [Gems](/guides/examples/gems/) for version selection without Bundler, or [Plugins](/guides/examples/plugins/) for a host whose plugins need incompatible gem APIs. [Source on GitHub](https://github.com/dtcristo/carton/tree/main/examples/bundler).

| Carton | `bigdecimal` | How it loads |
| --- | --- | --- |
| `math_helper` | `4.1.1` | imported by its directory from `main.rb`; uses `require 'bigdecimal'` |
| `billing` | none directly | imported by its directory from `main.rb`; imports `rounding` by its directory |
| `rounding` | `3.3.1` | `billing`'s Imported Carton and the app's Transitive Carton; sets up a Carton Bundle and uses `import 'bigdecimal'` |
| `cartoned_gem` | none | a path gem resolved by the app's bundle, then imported by name |

Each local Carton has a Gem-shaped Directory, such as `cartons/billing/` with Entrypoint `lib/billing.rb`, so `import_relative 'cartons/billing'` imports it without touching `$LOAD_PATH`.

## Run

```sh
bundle exec rake example:bundler
```

After the task installs the app bundle and Carton Bundles:

```sh
RUBY_BOX=1 ruby examples/bundler/main.rb
```

The integration suite also uses this example as a regression: separate Cartons keep their gem versions, the path gem imports cleanly, and the Main Box's activated gems stay unchanged. See [Gems and Bundler](/guides/bundler/).
