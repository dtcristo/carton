Customers and Billing are two Rails Engines, and each is imported as its own Carton. Customers registers customers. Billing imports Customers, validates invoices, calculates tax, and stores them. Rails loads once, in a framework Carton. A shop Carton mounts both Engines and exports the Rack app to Main. [Source on GitHub](https://github.com/dtcristo/carton/tree/main/examples/rails).

The example uses only public Rails, Zeitwerk, and Carton APIs. It adds no runtime patches. For Box ownership, setup, and limits, see the [Rails guide](/guides/rails/).

## Business workflow

1. `POST /customers` with `customer: { name: "Ada" }` registers a customer and returns its ID and trimmed name.
2. `POST /invoices.json` with `invoice: { customer_id: 1, subtotal_cents: 4200 }` issues an invoice for that customer. Billing imports Customers and uses its Directory to resolve the customer before persisting the invoice.
3. `GET /invoices/1.json` returns `id`, `customer_id`, `subtotal_cents`, `tax_cents`, and `total_cents`; `GET /invoices/1` renders HTML with the escaped customer name and total.

Both POSTs return 201. Tax is ten percent, rounded half up in integer cents, so 4200 gives 420 tax and 4620 total. The stored tax is kept when the invoice is read later. Blank customer names or invalid subtotals return 422 with domain errors. An unknown customer returns 404.

## Layout

```text
main.rb                                 # repeatable Rack demo, temporary SQLite
components/
  framework/lib/framework.rb             # shared Rails implementation and base classes
  customers/
    lib/customers.rb                     # Entrypoint, private framework Import, local loader
    lib/customers/{customer,directory,invalid_customer,engine}.rb
    app/models/customers/customer_record.rb
    app/repositories/customers/customer_repository.rb
    app/controllers/customers/
    config/routes.rb
    db/migrate/
  billing/
    lib/billing.rb                       # Entrypoint, imports Framework and Customers
    lib/billing/{invoice,issue_invoice,invalid_invoice,engine}.rb
    app/models/billing/invoice_record.rb
    app/repositories/billing/invoice_repository.rb
    app/controllers/billing/
    app/views/billing/invoices/show.html.erb
    config/routes.rb
    db/migrate/
  shop/
    bin/rails                            # explicit CLI bridge into the framework Carton
    config/{boot,application,environment,routes}.rb
    config/database.yml
    config.ru
    Rakefile
    lib/shop.rb                          # imports/registers domains and exports application
    lib/shop/application.rb
    test/integration/engines_test.rb
```

Repositories pass IDs and plain Hashes between Cartons. Each Engine's storage records use qualified names, such as `Customers::CustomerRecord` and `Billing::InvoiceRecord`. Associations still resolve across Carton boundaries. Controllers create their repositories per request, so no request state lives in the shared exported modules.

## How it fits together

Each Engine loads its own Ruby code with its own Zeitwerk loader. Its models, controllers, and repositories stay in its Carton. The loader also leaves the Engine's `app/` directories to Carton, so Rails' main autoloader does not claim them.

`isolate_namespace` keeps each Engine's names and routes separate. It does not choose a Box.

Rails finds each Engine's routes, migrations, and views as usual. The framework Carton registers the exported namespaces so Rails can look them up. It rejects name collisions and never copies their classes into Object.

The shop's `config/application.rb` imports `shop` rather than requiring it again, so there is one copy. The application class lives in the shop Carton. Main never loads Rails.

## Run

From the repository root:

```sh
bundle exec rake example:rails
```

The task installs the bundle, runs the temporary-database Rack demo, and runs the command and HTTP tests in fresh processes. It runs them with both lazy and eager loading. For a persistent local app, install the bundle, then run:

```sh
cd examples/rails/components/shop
RUBY_BOX=1 bin/rails db:prepare
RUBY_BOX=1 bin/rails routes
RUBY_BOX=1 bin/rails runner 'puts Customers::CustomerRecord.count'
RUBY_BOX=1 bin/rails zeitwerk:check
RUBY_BOX=1 bin/rails test
RUBY_BOX=1 bin/rails server -b 127.0.0.1
```

Each Engine exposes its migrations to Rails, so `db:prepare` creates the tables; importing the app creates none. Development and test use separate databases under `shop/storage/`. Set `SHOP_DATABASE` to choose another path. Generated databases, schemas, and logs are git-ignored.

## CLI and limits

Use the shop's `bin/rails`. It enters the framework Carton, sets Rails' standard `APP_PATH` there, and makes the exported namespaces available to `runner`. Rails source loads only in the framework Carton. Verified commands are `db:prepare`, `db:migrate`, `routes`, `runner`, `zeitwerk:check`, `test`, and `server` with Puma. Stock `bundle exec rails`, direct `rake`, the console, and generators are not covered. Boot Imports live inside modules because Rake also defines a top-level `import`.

Restart the server after edits. The separate [reloading spike](https://github.com/dtcristo/carton/tree/main/spikes/rails_reloading) copies this app and tests two serial Customers and Billing replacements with private hooks. This example never loads those hooks. Shared Rails classes and registries are still mutable objects, and Active Support patches stay Box-local. Jobs, mailers, external queues, and other Rails subsystems are outside this example.
