Customers and Billing are two Hanami slices, and each is imported as its own Carton. Customers registers customers. Billing imports Customers, validates invoices, calculates tax, and stores them. The framework Carton loads Hanami, Dry, and Rom once. The shop Carton exports its Rack app to Main. [Source on GitHub](https://github.com/dtcristo/carton/tree/main/examples/hanami).

This is the same workflow as the [Rails example](/guides/examples/rails/). The example uses only public Hanami, Dry, Rom, and Carton APIs, and it patches nothing.

## Business workflow

1. `POST /customers` with `customer: { name: "Ada" }` registers a customer and returns its ID and trimmed name.
2. `POST /invoices.json` with `invoice: { customer_id: 1, subtotal_cents: 4200 }` issues an invoice for that customer. Billing imports Customers and uses its Directory to resolve the customer before persisting the invoice.
3. `GET /invoices/1.json` returns `id`, `customer_id`, `subtotal_cents`, `tax_cents`, and `total_cents`; `GET /invoices/1` renders HTML with the escaped customer name and total.

Both POSTs return 201. Tax is ten percent, rounded half up in integer cents: 4200 produces 420 tax and 4620 total. Stored tax is retained when the invoice is read later. Contract errors return 422 with field errors, and malformed JSON or a non-object body returns 400; an unknown customer or invoice returns 404.

## Layout

```text
Gemfile, Gemfile.lock                        # one locked bundle; path gems for each Carton
main.rb                                      # repeatable Rack demo, temporary SQLite
test/                                        # command, HTTP, and isolation tests
cartons/
  framework/
    lib/framework.rb                         # Framework Entrypoint; owns Hanami, Dry, and Rom
    lib/framework/{prepare,cli}.rb           # anchored framework lifecycle and CLI
  customers/
    lib/customers.rb                         # Entrypoint, imports Framework, local Zeitwerk loader
    lib/customers/config/slice.rb            # Hanami slice rooted in this Carton
    lib/customers/{actions,operations,contracts,repos,relations}/
  billing/
    lib/billing.rb                           # Entrypoint, imports Framework and Customers
    lib/billing/config/{slice,providers/customer_directory}.rb
    lib/billing/{actions,operations,contracts,repos,relations,views,templates}/
  shop/
    lib/shop.rb                              # imports and registers domains, exports Shop::App
    config.ru                                # Rack bootstrap imports Shop
    bin/hanami                               # CLI bootstrap imports Shop, then enters Framework
    config/
      boot.rb                                # sets up Bundler for the shop's Imports
      app.rb                                 # Hanami app configuration and JSON body parser
      routes.rb                              # slice routes
      slices/{customers,billing}.rb          # import and bind the existing slice namespaces
      providers/db.rb                        # DATABASE_URL and derived test database
      db/migrate/                            # shared schema, run by the Hanami CLI
```

Repositories pass IDs and plain Hashes between Cartons. Customers' Directory returns a plain customer Hash, so Billing never touches Customers' repos or relations.

## How it fits together

The shop's Entrypoint imports Framework and loads `Shop::App` from `config/app.rb`. Hanami finds the slices in `config/slices/`. Each slice file imports its Carton instead of requiring a second copy.

Each Carton loads its own code with its own Zeitwerk loader and tells Hanami's loader to skip that source tree. Hanami still wires the components and provides the `Deps` mixin. When a component is resolved, the Carton's autoload runs. Actions, operations, contracts, and repos therefore run in their domain's Carton, in both lazy and eager modes. Slice configuration, providers, and migrations run in Framework. Setting `HANAMI_EAGER_LOAD=true` boots all providers and components up front, after migrating.

Each exported namespace is bound in the framework Box by its own `Framework.register` call. Shop registers Customers and Billing from its slice files, `config/slices/customers.rb` and `config/slices/billing.rb`, and registers itself from `lib/shop.rb`. Registering the same module again is allowed. Registering a different module under the same name is rejected.

Framework also keeps its deferred requires in its own Box. Without that, a require made during a nested Import could load part of Dry into the importing Carton. Main receives no Hanami, Dry, or Rom constants.

## Run

From the repository root:

```sh
bundle exec rake example:hanami
```

The task installs the bundle, runs the temporary-database demo, and runs the command and HTTP tests in fresh processes. It runs them with both lazy and eager loading. For a persistent local app, install the bundle, then run:

```sh
cd examples/hanami/cartons/shop
RUBY_BOX=1 bin/hanami db migrate
RUBY_BOX=1 bin/hanami routes
RUBY_BOX=1 bin/hanami run 'puts Hanami.app.slices.keys.inspect'
RUBY_BOX=1 bin/hanami server --host=127.0.0.1 --port=2300
```

Development and test use separate SQLite databases under `cartons/shop/db/`. Set `DATABASE_URL` to choose another, and the test database name is derived from it. Generated databases and logs are git-ignored. Migrations create the tables; importing Shop creates none.

## CLI and limits

Use the shop's `bin/hanami`. It imports Shop before invoking the standard CLI in Framework. Verified commands are `db migrate`, `routes`, `run`, and `server`. Stock `bundle exec hanami`, generators, the console, asset builds, mailers, and background jobs are not covered. Restart after source edits, since no Carton reloading hooks are installed. Shared framework classes and registries are still mutable objects, as in the Rails example.
